# План адресации сети парка - 10.10.10.0/24, зона lab.internal

## Общие параметры сети

* **Сеть (CIDR):** `10.10.10.0/24`
* **Маска подсети** `255.255.255.0`
* **Шлюз по умолчанию (Gateway)** `10.10.10.1`
* **Доменный суффикс** `lab.internal`
* **Широковещательный адрес (Broadcast):** `10.10.10.255`

## Границы зон и обоснование архитектуры

1. **Разделение статики и DHCP:**
   * **Статический диапазон (`.1` – `.99`):** Выделен под инфраструктурные узлы, серверы и резервы расширения.
   * **DHCP-пул (`.100` – `.200`):** Начинается со `.100` и строго изолирован от статической зоны, что полностью исключает дублирование адресов (IP conflicts).
2. **Запас под Project 02 (Мониторинг):**
   * Адреса `.31`–`.39` выделены сразу «встык» к управляющему узлу `mgmt` (`.30`). Для вспомогательных сервисов управления (Grafana, Prometheus, Loki) в едином адресном блоке с целевой машиной.
3. **Запас под Project 03 (Сбои и новые узлы):**
   * Диапазон `.41`–`.99` оставляет 59 свободных статических адресов. Этого с запасом хватит для поднятия дочерних виртуалок, узлов-дублеров или балансировщиков в ходе тестирования отказоустойчивости.
